# Knowledge

Research and reference material that informs product decisions — **not** application code, and not shipped to users directly. Content here gets distilled into code (the seeded treatment catalog, Learn articles, milestone copy) rather than read at runtime.

Drop files in as plain markdown. No naming rules; a short note at the top of each file saying where it came from and how much to trust it is more useful than any filing system.

## What's most useful to add

For the **routine selection page** specifically, the highest-value input is anything that pins down the *shape* of real-world routines:

- **Which treatments people actually combine**, and in what patterns (the presets should mirror real stacks, not permutations)
- **Typical frequency per treatment** — daily, 2×/day, 3×/week, etc. This directly seeds each item's default schedule, which is the main thing that makes setup fast instead of tedious
- **Naming people actually use** — brand vs. generic, common abbreviations (LLLT, derma roller, "min", "fin", "dut"). Feeds the autocomplete list
- **Typical strengths/dosages** — e.g. minoxidil 2% / 5%, finasteride 1mg. Lets the dosage field offer suggestions instead of being a blank box
- **What's device-based vs. topical vs. oral**, where it's ambiguous

Also valuable, for the milestone/expectation work discussed separately:

- **Timeline expectations** — when shedding typically starts and settles, when results typically appear
- **Anything about why people quit**, especially early

## Guidance on sourcing

This app deliberately does not diagnose, recommend treatments, or make medical claims (PRD §3). Research here should describe *what people do and how they describe it*, so the app can track it accurately in their own words. Where a claim is medical rather than descriptive, note the source so the user-facing copy can stay appropriately hedged.
